# IPSP MQTT/TLS wolfSSL/wolfMQTT

Experimental project for communicating an `nRF5340 DK` with a Linux host using
MQTT over TLS through Bluetooth LE IPSP / IPv6-over-BLE.

The firmware runs as an MQTT/TLS client using wolfSSL + wolfMQTT. The computer
runs the wolfMQTT TLS broker and creates the Linux `bt0` interface through IPSP.

## Architecture

```text
nRF5340 DK
  BLE IPSP
  IPv6: 2001:db8::1
  wolfMQTT client + wolfSSL TLS 1.3
        |
        | BLE 6LoWPAN / IPSP
        v
Linux bt0
  IPv6: 2001:db8::2
  wolfMQTT broker + wolfSSL TLS 1.3
  TCP port: 8883
```

MQTT topics:

- `nrf5340/command`: commands sent to the board.
- `nrf5340/telemetry`: telemetry published by the board.

Commands accepted by the board:

- `led:on`
- `led:off`
- `led:toggle`

## Requirements

- CachyOS/Arch Linux with working Bluetooth.
- nRF Connect SDK `v2.6.0`. This version still includes Zephyr IPSP support.
- `nrfutil` with the `sdk-manager` command.
- `openssl`, `mosquitto`, `bluez`, `iproute2`.
- The `nRF5340 DK` connected through the debugger/J-Link USB port.

On Arch/CachyOS:

```sh
sudo pacman -S openssl mosquitto bluez bluez-utils iproute2
```

## 1. Fetch wolfSSL and wolfMQTT

The wolf modules are not versioned in this repository. Fetch them locally:

```sh

```

This creates:

- `modules/wolfmqtt`

## 2. Apply the Zephyr IPSP Patch

The Zephyr tree from NCS `v2.6.0` may emit logs such as:

```text
Ignoring invalid L2CAP TX metadata 0x20005202
```

In the IPSP + MQTT/TLS flow, this happens because L2CAP stores metadata in
`net_buf_user_data()`, while the `bt_conn_send_cb()` layer also reuses this
field during TX. During segmented transmission, the callback may receive an
overwritten metadata pointer.

This repository includes the patch:

```text
patches/zephyr-v2.6.0-l2cap-tx-metadata.patch
```

Apply it to the Zephyr tree from NCS `v2.6.0`:

```sh
cd /home/[USER]/ncs/v2.6.0/zephyr
git apply /home/[USER]/Documents/canada/pesquisa/ipsp_mqtt_tls_wolf/patches/zephyr-v2.6.0-l2cap-tx-metadata.patch
```

If the patch is already applied, `git apply` may fail because the hunks no
longer apply. In that case, check the current diff with:

```sh
git diff -- subsys/bluetooth/host/l2cap.c
```

## 3. Generate TLS Certificates

```sh
cd /home/[USER]/Documents/canada/pesquisa/ipsp_mqtt_tls_wolf
./host/gen_tls_certs.sh 2001:db8::2 localhost
```

The generated CA in `host/certs/ca.crt` is embedded in
`firmware/src/main.c`. If you generate new certificates, update the
`ca_cert_pem` string in the firmware before building.

## 4. Build and Flash the Firmware

Build:

```sh
cd /home/[USER]/Documents/canada/pesquisa/ipsp_mqtt_tls_wolf
env SHELL=/bin/bash /home/[USER]/.local/bin/nrfutil sdk-manager toolchain launch \
  --ncs-version v2.6.0 \
  --chdir /home/[USER]/ncs/v2.6.0/nrf \
  -- west build \
     -d /home/[USER]/Documents/canada/pesquisa/ipsp_mqtt_tls_wolf/firmware/build \
     -b nrf5340dk_nrf5340_cpuapp \
     --sysbuild \
     -p always \
     /home/[USER]/Documents/canada/pesquisa/ipsp_mqtt_tls_wolf/firmware
```

Flash:

```sh
cd /home/[USER]/Documents/canada/pesquisa/ipsp_mqtt_tls_wolf
./scripts/flash_firmware.sh
```

The `flash_firmware.sh` script programs the HEX files generated by sysbuild
using `nrfutil device program`, avoiding incompatibilities between the older
Zephyr/NCS `v2.6.0` runner and newer `nrfutil` versions.

To monitor board logs, use the second J-Link serial port:

```sh
tio /dev/ttyACM1 -b 115200
```

## 5. Connect IPSP on Linux

With the board powered on and advertising `nRF5340 IPSP MQTT TLS`, connect the
host:

```sh
cd /home/[USER]/Documents/canada/pesquisa/ipsp_mqtt_tls_wolf
sudo ./host/ipsp_connect.sh F8:69:5E:1E:CE:2F 2
```

Replace `F8:69:5E:1E:CE:2F` with the BLE address advertised by your board. Type
`2` means LE random address, which is the common case for this firmware.

The script:

- mounts `debugfs` if needed;
- loads `bluetooth_6lowpan`;
- enables `/sys/kernel/debug/bluetooth/6lowpan_enable`;
- asks the kernel to connect the IPSP peer;
- waits for the `bt0` interface;
- configures `2001:db8::2/64` on the host.

Test IPv6:

```sh
ping -6 -c 3 -I bt0 2001:db8::1
```

## 6. Run the TLS Broker on the Host

```sh
cd /home/[USER]/Documents/canada/pesquisa/ipsp_mqtt_tls_wolf
./host/build_wolf_broker.sh
./host/run_wolf_broker.sh
```

The broker listens with TLS on port `8883`. The host build compiles a local
wolfSSL into `host/build/wolfssl-on-install` or
`host/build/wolfssl-off-install` and generates the
`host/build/wolfmqtt-broker` executable.

To choose whether the broker uses PQC in the TLS handshake:

```sh
./host/build_wolf_broker.sh --pqc on
./host/build_wolf_broker.sh --pqc off
```

The final executable remains `host/build/wolfmqtt-broker`; build it with the
same PQC mode that you intend to use in the firmware.

## 7. TLS 1.3 with ML-KEM

The firmware and broker force the standalone TLS 1.3 group `MLKEM768`. The
current PQC mode does not advertise a classic fallback or hybrid group for the
board connection or for commands sent through Mosquitto/OQS.

PQC mode is enabled by default. To disable it in the firmware, use the overlay:

```sh
west build ... -- -DEXTRA_CONF_FILE=/home/[USER]/Documents/canada/pesquisa/ipsp_mqtt_tls_wolf/firmware/pqc_off.conf
```

From the interactive console, use:

```text
build broker --pqc on
build firmware --pqc on
build broker --pqc off
build firmware --pqc off
```

The firmware build enables:

- `WOLFSSL_MLKEM=yes`
- `WOLFSSL_PQC_HYBRIDS=no`
- `WOLFSSL_TLS_NO_MLKEM_STANDALONE=no`

The broker automatically applies the patch:

```text
patches/wolfmqtt-broker-force-mlkem-group.patch
```

When connecting, the expected logs include:

```text
TLS 1.3 key exchange group: MLKEM768
broker: TLS 1.3 group MLKEM768
broker: TLS handshake done sock=N TLSv1.3
```

The `on`, `off`, and `toggle` commands from `board_console.sh` also use
Mosquitto with the OQS provider when `PQC=on`. By default, the script expects
the provider at:

```text
/home/thiago/Documents/canada/pesquisa/oqs-openssl/install
```

To point to a different prefix:

```sh
OQS_PREFIX=/path/to/oqs/install ./scripts/board_console.sh
```

## 8. Test MQTT

Subscribe to telemetry:

```sh
cd /home/[USER]/Documents/canada/pesquisa/ipsp_mqtt_tls_wolf
OQS_PREFIX=/home/thiago/Documents/canada/pesquisa/oqs-openssl/install
OPENSSL_CONF=$PWD/host/openssl-oqs.cnf \
OPENSSL_MODULES=$OQS_PREFIX/lib/ossl-modules \
LD_LIBRARY_PATH=$OQS_PREFIX/lib \
mosquitto_sub -h 127.0.0.1 -p 8883 \
  --cafile host/certs/ca.crt \
  --insecure \
  -t nrf5340/telemetry
```

Turn the LED on/off or toggle it:

```sh

LD_LIBRARY_PATH=$OQS_PREFIX/lib \
mosquitto_pub -h 127.0.0.1 -p 8883 --cafile host/certs/ca.crt --insecure \
  -t nrf5340/command -m 'led:on'

OPENSSL_CONF=$PWD/host/openssl-oqs.cnf \
OPENSSL_MODULES=$OQS_PREFIX/lib/ossl-modules \
LD_LIBRARY_PATH=$OQS_PREFIX/lib \
mosquitto_pub -h 127.0.0.1 -p 8883 --cafile host/certs/ca.crt --insecure \
  -t nrf5340/command -m 'led:off'

OPENSSL_CONF=$PWD/host/openssl-oqs.cnf \
OPENSSL_MODULES=$OQS_PREFIX/lib/ossl-modules \
LD_LIBRARY_PATH=$OQS_PREFIX/lib \
mosquitto_pub -h 127.0.0.1 -p 8883 --cafile host/certs/ca.crt --insecure \

On the board console, you should see messages such as:

```

## 9. Board Interactive Console

To monitor the board serial output and send short MQTT commands from the same
terminal:

```sh
cd /home/thiago/Documents/canada/pesquisa/ipsp_mqtt_tls_wolf
./scripts/board_console.sh
```

The script monitors `/dev/ttyACM1` with `tio`, subscribes to
`nrf5340/telemetry`, and opens an interactive prompt. Commands:

```text
build broker [--pqc on|off] [--keylog on|off]
                         build host/build/wolfmqtt-broker
build firmware [--pqc on|off]
                         build firmware/build/merged.hex and merged_CPUNET.hex
connect                  connect IPSP using F8:69:5E:1E:CE:2F random
connect public           connect the default MAC using public address type
connect AA:BB:CC:DD:EE:FF random
connect AA:BB:CC:DD:EE:FF public
broker on                start the local wolfMQTT TLS broker
broker off               stop the broker started by this console
broker restart           restart the broker
broker status            show whether the broker is running in this console
broker clean-port        clear stale TCP state on port 8883
flash                    flash firmware after checking USB/J-Link with nrfutil
on                       send led:on
off                      send led:off
toggle                   send led:toggle
status                   show the current configuration
help                     show help
quit                     exit
```

Useful variables:

```sh
TTY_DEVICE=/dev/ttyACM1 ./scripts/board_console.sh
IPSP_ADDR=AA:BB:CC:DD:EE:FF IPSP_ADDR_TYPE=public ./scripts/board_console.sh
SERIAL_NUMBER=1050032722 ./scripts/board_console.sh
SHOW_TELEMETRY=0 ./scripts/board_console.sh
MQTT_HOST=127.0.0.1 MQTT_PORT=8883 ./scripts/board_console.sh
NCS_VERSION=v2.6.0 BOARD=nrf5340dk_nrf5340_cpuapp ./scripts/board_console.sh
OQS_PREFIX=/home/thiago/Documents/canada/pesquisa/oqs-openssl/install ./scripts/board_console.sh
PQC=off ./scripts/board_console.sh
```

The `build broker` command calls `host/build_wolf_broker.sh`. The
`build firmware` command calls `nrfutil sdk-manager toolchain launch` with
`west build` using `NCS_VERSION`, `NCS_CHDIR`, and `BOARD`.

The `flash` command calls `scripts/flash_firmware.sh`. Before flashing, it runs
`nrfutil device list` and continues only if it finds the serial number
configured in `SERIAL_NUMBER`.

The broker started by `broker on` is automatically stopped when
`board_console.sh` exits.

When `broker on` is used, the console also supervises the broker log. If the
broker reports a TLS handshake timeout, the console stops that broker instance,
clears stale TCP state, runs `connect` again with the configured IPSP address,
and starts the broker again. The firmware and broker handshake timeout are both
configured for 30 seconds.

The console forces Mosquitto to use `--tls-version tlsv1.3` for command and
telemetry connections. Broker TLS keylog export is disabled by default because
it can interfere with Mosquitto/OpenSSL handshakes in this setup; enable it only
when debugging packet captures:

```text
build broker --pqc on --keylog on
```

## 10. Docker Container for the Server Side

The repository includes a Docker runtime for the host/server side of the test:

- `wolfmqtt-broker` with wolfSSL;
- `mosquitto_pub` and `mosquitto_sub`;
- OpenSSL with the OQS provider for `MLKEM768`;
- Linux IPSP tools such as `bluez`, `iproute2`, `kmod`, and `tcpdump`;
- an optional command to apply the Zephyr/NCS `v2.6.0` patch.

Important: IPSP/IPv6-over-BLE depends on the host Linux kernel. For that
reason, the container uses `network_mode: host`, runs privileged, and mounts
`/dev`, `/sys/kernel/debug`, `/var/run/dbus`, and `/lib/modules`.

On CachyOS/Arch, install Docker if needed:

```sh
sudo pacman -S docker docker-compose
sudo systemctl enable --now docker
sudo usermod -aG docker "$USER"
```

Log out and log back in for the `docker` group to take effect, or use
`sudo docker`.

Build the image:

```sh
cd /home/thiago/Documents/canada/pesquisa/ipsp_mqtt_tls_wolf
docker compose -f docker-compose.server.yml build
```

If your Docker installation does not support the `docker compose` plugin and
prints `unknown shorthand flag: 'f' in -f`, install Docker Compose or use the
compatibility wrapper:

```sh
sudo pacman -S docker docker-compose
sudo systemctl enable --now docker

./scripts/docker_server.sh build
```

Prepare the project dependencies inside the mounted volume:

```sh
docker compose -f docker-compose.server.yml run --rm ipsp-server setup
```

This command fetches `modules/wolfssl` and `modules/wolfmqtt`, generates
certificates if they do not exist yet, and builds `host/build/wolfmqtt-broker`.

To apply the IPSP patch to the NCS `v2.6.0` tree mounted at `/ncs/v2.6.0`:

```sh
docker compose -f docker-compose.server.yml run --rm ipsp-server apply-ncs-patch
```

Connect IPSP and create `bt0`:

```sh
docker compose -f docker-compose.server.yml run --rm ipsp-server \
  connect F8:69:5E:1E:CE:2F 2
```

Run the TLS broker:

```sh
docker compose -f docker-compose.server.yml run --rm ipsp-server broker
```

In another terminal, send MQTT commands:

```sh
docker compose -f docker-compose.server.yml run --rm ipsp-server pub led:on
docker compose -f docker-compose.server.yml run --rm ipsp-server pub led:off
docker compose -f docker-compose.server.yml run --rm ipsp-server pub led:toggle
docker compose -f docker-compose.server.yml run --rm ipsp-server ping
```

Subscribe to telemetry:

```sh
docker compose -f docker-compose.server.yml run --rm ipsp-server sub
```

Clear stale sockets on port `8883` after a handshake failure:

```sh
docker compose -f docker-compose.server.yml run --rm ipsp-server clean-port
```

Check whether the OQS provider is loaded:

```sh
docker compose -f docker-compose.server.yml run --rm ipsp-server oqs-check
```

You can also open a shell in the environment:

```sh
docker compose -f docker-compose.server.yml run --rm ipsp-server shell
```

To launch the existing board console inside the Docker server-side runtime,
use:

```sh
./scripts/board_console.sh --docker
```

This relaunches `board_console.sh` through `docker-compose.server.yml` and uses
the container-provided OpenSSL/OQS, Mosquitto clients, BlueZ/IPSP tools, and
broker build. The firmware build and flash commands are still intended for the
native host workflow unless you also provide the required nRF tooling inside
the container.

Container limits:

- it covers the server/host side of the test;
- firmware build/flash is still simpler outside the container with
  `nrfutil sdk-manager`, as described in the previous sections;
- if you generate new certificates inside the container, the CA embedded in
  `firmware/src/main.c` must still match, or the firmware must be rebuilt and
  flashed again.

## Implementation Notes

- The firmware uses TLS 1.3 with wolfSSL. By default, the handshake forces the
  standalone `MLKEM768` group; use `build firmware --pqc off` and
  `build broker --pqc off` to test the classic TLS 1.3 path.
- MQTT keepalive is maintained explicitly: when `MqttClient_WaitMessage()`
  returns a timeout, the firmware sends `MqttClient_Ping()`.
- The broker is used in TLS-only mode on port `8883`.
- `firmware/build/`, `host/build/`, `modules/`, and `tools/` are generated
  locally and should not be committed.
